## 1. Concrete Remaining Blockers

### Blocker 1: Ephemeral File Storage on Render
* **Description:** The system currently relies on `src/db/local_store.json`. Deploying to Render without a persistent volume means any changes made on production (new candidate registrations, applications, published jobs) will be wiped when Render restarts or redeploys the web service.
* **Severity:** `P0_CRITICAL` for production deployment.
* **Smallest Safe Solution:**
  - Create a Render Persistent Disk mounted at `/var/data` and point `CHAKRI_DB_FILE=/var/data/local_store.json`.
  - Alternatively, attach an external PostgreSQL / MongoDB database connection.

### Blocker 2: Local Ollama Model Availability
* **Description:** Ollama is not on the Windows system PATH. Autonomous local LLM diagnostic reasoning cannot run on the worker PC without Ollama being installed and serving a model (e.g. `qwen2.5:1.5b`).
* **Severity:** `P2_MEDIUM` (Worker currently uses deterministic heuristic and Playwright tests instead).
* **Smallest Safe Solution:**
  - User can download and start Ollama on port 11434 (`ollama run qwen2.5:1.5b`), OR configure a Gemini API key as a cloud diagnostic fallback.

### Blocker 3: Remote Cloud Access to Screenshot Artifacts
* **Description:** Screenshots generated by Playwright are saved in the local artifact folder (`C:\Users\Leon Rahman\.gemini\antigravity\brain\...`). Remote webhooks or cloud n8n orchestrators cannot view these images.
* **Severity:** `P2_MEDIUM`.
* **Smallest Safe Solution:**
  - Add an authenticated admin route (`/api/admin/artifacts/[name]`) that serves evidence screenshots, or upload them to a free Cloudflare R2 bucket.
